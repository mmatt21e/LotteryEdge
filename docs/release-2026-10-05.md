# Audited data-quality release 0.6.1

This release publishes the tested personal-use corrections after Nebraska PR #9. It does not introduce paid features or claim improved chances of winning.

- Georgia uses official display-dollar values. Versioned corrections support older snapshots without guessing historical units. The official source's old as-of date remains old even when fetched today.
- Invalid prize counts, unsupported or contradictory ticket anchors, partial prize ladders and inconsistent stored EV values are excluded with reasons. No artificial payout floor or fallback probability converts invalid data into a supported estimate.
- Import time is distinct from results date. Explicit official dates take precedence; otherwise the previous publisher-local calendar day is labeled assumed. Failed attempts retain old snapshot dates. Per-source and combined views show their actual date coverage.
- Stale, failed and paused feeds do not contribute current EV rankings, model odds, confidence claims or change alerts. Lite historical lists remain labeled historical. Winner claim/post dates are preserved.
- Collector writes preserve prior published snapshots, history and winner files under versioned observation archives. The release does not rewrite old root snapshots. Ledger/favorite storage schema and code are unchanged.
- Arkansas scratcher and winner collectors fail closed on the documented access block. Connecticut's scraping prohibition and Oklahoma's permission-review pause remain active. Virginia's blocked browser adapter is disabled and removed from the scheduled workflow. No access workaround is included.
- Nebraska retains the verified Python/PDF setup from PR #9. Its date compatibility helper delegates to the same shared date logic as the application.
- The PWA now displays version 0.6.1 and prompts before a waiting service-worker update reloads an open app. Users should save any unfinished ticket entry first. Existing local storage is retained. `build-info.json` records the exact post-refresh Git revision, the workflow's starting revision and build time.

Validation before publication: 80 root tests, 48 frontend tests, three Python PDF test cases, root TypeScript check and web TypeScript/Vite/PWA build. Fixtures cover the original invalid Ohio/Massachusetts examples, September 2 to September 1, source dates, DST/calendar boundaries, stale confidence, daily-delta gaps, literal Georgia dollars, and no-network source pauses.

The authorized deployment runs the existing scheduled pipeline once after review/merge. A successful job is not evidence that every source is current; inspect source dates, explicit exclusions and per-state status. Remaining permission/access blocks are intentional limitations. The schedule remains 11:00 UTC daily on the default branch.

Older maintenance notes record the earlier local investigation and should be read with this release note and `docs/nebraska-pdf.md` for current Actions support.
